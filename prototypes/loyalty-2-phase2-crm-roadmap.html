Delivery Principles
Push first.
Speed over perfection.
Phase 2 shifts from enrollment to activation. The priority: turn passive point earners into active redeemers using the fastest channels first.
01

Push First

Lock screen before inbox. Minimal creative, maximum speed. Get campaigns live in days, not weeks. Meet the Efficient Inspired where they already are: glancing at their phone between tasks.

02

Data Gated

Each wave unlocks as Talon.one data pipelines come online. Wave 1 needs only points balance and opt-in status. Wave 2 needs goal progress per customer.

03

Template Thinking

Design once, populate many. Goal comms, new rewards alerts, and points summaries all use consistent variable structures so templates work the moment data flows.

Tone of Voice Approach

All copy in this roadmap follows the HelloFresh Global TOV: punchy bursts over paragraphs, memorable rhythm, food as the hero, and movement energy. Written for the Efficient Inspired audience: time-poor, autonomy-driven, and looking for the win in every weeknight.

Data Dependencies
What we need.
Where it comes from.
Each wave is gated by data availability from Talon.one and the DWH. Here's what unlocks what.

Points Balance

Current total per customer. Required for: Use Your Points, Points Balance Module, Reward Redemption, Gap-to-Reward calculations.

Source: Talon.one • Unlocks: Wave 1+

Points Earned Per Action

Breakdown by order and goal type per customer. Required for: Monthly Points Summary, Points Earned email, Loyalty Purchase attribution.

Source: Talon.one • Unlocks: Wave 2

Goal Progress Per Customer

Which goals started, completed, or outstanding per customer. Required for: Goal comms suite (activation, mid-progress, completion).

Source: Talon.one • Unlocks: Wave 2

Goals & Rewards Catalogue

Active goals and available rewards at any point in time. Required for: Goal activation, New Rewards comms, Points Balance Module.

Source: DWH • Unlocks: Wave 1 (partial), Wave 2 (full)
Analytics Request
Event-Based Triggers
for Push Campaigns
Each push campaign requires a specific event from the analytics pipeline. Below are the trigger specifications to request from the data team, with exact event names, logic, required fields, timing, and suppression rules.

Points Balance Threshold

rewards_points_redeemable
Logic
Customer's points_balance >= minimum redemption threshold for any active reward in catalogue
Required Data
customer_id, points_balance, lowest_reward_cost, reward_name (cheapest claimable)
Frequency
Fire once per customer per reward eligibility change (not continuously)
Source
Talon.one points balance + Rewards catalogue
Suppression
Suppress if customer redeemed in last 7 days
Use Your Points (Wave 1)

Points Earned Confirmation

rewards_points_earned
Logic
Customer earns points from any action (order, goal completion, referral, recipe rating, add-on, etc.)
Required Data
customer_id, points_earned, points_balance, earning_action (e.g. "order", "referral", "recipe_rating"), action_description
Timing
Fire immediately upon points credit (real time)
Source
Talon.one points credit event
Suppression
Cap at max 1 points earned push per day (batch multiple small actions into one notification if needed)
Points Earned Confirmation (Wave 1)

Goal Launch

rewards_goal_launched
Logic
New goal type becomes active in Talon.one catalogue
Required Data
goal_id, goal_name, goal_action, points_value, timeframe
Frequency
One event per goal launch (batch send to all opted in members)
Source
Talon.one goal catalogue / manual trigger
Specific Goal Launch Comms (Wave 1) General Goal Awareness (Wave 1)

Global Suppression Rules

  • Customer must be push opted in
  • Do not stack more than 2 Rewards pushes in a single day per customer
  • Suppress all triggers if customer has unsubscribed from the loyalty programme
  • Each event should pass all listed required data fields so CRM can template the push copy with personalisation tokens
